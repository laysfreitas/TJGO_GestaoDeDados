Crie um app completo em Python Flask (um único servidor) com SQLAlchemy (PostgreSQL via psycopg2-binary lendo DATABASE_URL das Secrets do Replit) e interface em HTML + TailwindCSS via CDN (sem Node/Vite). O sistema chama “Sistema de Formulários” e deve cobrir o fluxo Iniciado → Em elaboração → Em revisão → Pronto para envio com transições controladas e validação de campos obrigatórios por estágio. Estruture o projeto com: app.py (cria o Flask, configura DB, registra blueprints, roda em 0.0.0.0:5000), models.py (tabelas e relacionamentos), routes.py (CRUD e transições), database.py (fábrica do SQLAlchemy), pasta templates/ (base.html, index.html, form_list.html, form_edit.html, form_view.html) e static/ (css/style.css). Modelo principal Formulario deve conter, por estágio: Iniciado → n_processo (String), interessado (String), magistrado (String), comarca (String), serventia (String), dt_despacho (Date), dt_encaminhamento (Date), hr_encaminhamento (Time), dt_recebimento (Date), hr_recebimento (Time); Em elaboração → id_prazo (FK prazo.id), id_status (FK status.id), relações prazo e status, qt_objetos (Integer), nota_tecnica (String); Em revisão → mesmos campos de elaboração, mas registrar id_revisor (FK usuario.id) e data/hora de revisão; Pronto para envio → id_responsavel_envio (FK usuario.id), relação responsavel_envio, dt_envio (Date), hr_envio (Time), forma_envio (String), forma_envio_email (String), id_anexo_parecer (FK documento.id, ondelete='SET NULL', nullable), relação anexo_parecer. Gere também as tabelas auxiliares Prazo(id,nome), Status(id,nome), Usuario(id,nome,email), Documento(id,nome_arquivo,url/opcional), com seed mínimo (alguns prazos, statuses e usuários). Implemente enum/campo status_formulario com os valores INICIADO, ELABORACAO, REVISAO, PRONTO_ENVIO; regras de transição: só avançar/voltar um estágio por vez; ao avançar, valide os campos obrigatórios do próximo estágio (retorne mensagem clara se faltar). Rotas: página inicial lista com filtros por status e busca; criar/editar formulário; visualizar detalhes; ações de transição (/transicao/<id>?acao=avancar|voltar); upload simples opcional para Documento (pode simular com URL). Templates: form_list.html mostra cards/tabela com status e botões “Editar”, “Avançar”, “Voltar”; form_edit.html organiza os campos por abas/seções (Iniciado/Elaboração/Revisão/Envio) e só habilita a seção do estágio atual; base.html inclui Tailwind via CDN e um componente de barra de progresso (4 passos) refletindo o status_formulario. Inclua validação no servidor e feedback no template (flash messages). Crie requirements.txt com Flask, Flask_SQLAlchemy, psycopg2-binary, python-dotenv (carregar .env local). Ao iniciar, se o banco estiver vazio, crie as tabelas e aplique o seed. Adicione README com: como definir DATABASE_URL nas Secrets do Replit (ex.: postgresql+psycopg2://usuario:senha@host:5432/banco), como rodar (python app.py), e como usar. Configure o .replit para rodar python app.py. Garanta mensagens de erro amigáveis para transição inválida ou campos faltantes e bloqueie edição de seções de estágios anteriores.
